# GPS API Test Map - Руководство пользователя

## 🎯 Назначение

Интерактивная HTML страница для тестирования нового GPS API и визуализации позиций автобусов на карте в реальном времени.

## 🚀 Запуск

### 1. Запустить приложение

```bash
cd /home/developer/projects/bus/ugur_v4/bus-route-backend
./mvnw spring-boot:run
```

### 2. Открыть тестовую страницу

Откройте в браузере:
```
file:///home/developer/projects/bus/ugur_v4/bus-route-backend/gps-test-map.html
```

Или через HTTP сервер:
```bash
# Python 3
python3 -m http.server 8000

# Затем откройте http://localhost:8000/gps-test-map.html
```

## 📋 Функционал

### Основные возможности

1. **Загрузка данных**
   - Выбор количества автобусов (10, 50, 100, все)
   - Ручная загрузка или авто-обновление
   - Настройка интервала обновления (5-300 сек)

2. **Карта**
   - Интерактивная карта с OpenStreetMap
   - Маркеры автобусов:
     - 🟢 Зеленые - в движении (speed > 0)
     - 🔴 Синие - остановлены
   - Клик на маркер - детальная информация
   - Авто-масштабирование для отображения всех автобусов

3. **Список автобусов**
   - Список всех загруженных автобусов
   - Клик на автобус - фокус на карте
   - Статус движения в реальном времени

4. **Статистика**
   - Всего автобусов
   - Автобусы в движении
   - Средняя скорость
   - Время последнего обновления

## 🎮 Использование

### Шаг 1: Настройка параметров

1. **API Endpoint** - URL вашего backend API
   - По умолчанию: `http://localhost:8080/api/vehicles/positions`
   - Можно изменить для тестирования других окружений

2. **Количество автобусов**
   - 10 - для быстрого теста
   - 50 - оптимально для визуализации
   - 100 - большой датасет
   - Все - полная загрузка (может быть медленно)

3. **Интервал обновления**
   - Минимум: 5 секунд
   - Рекомендовано: 30 секунд
   - Максимум: 300 секунд (5 минут)

### Шаг 2: Загрузка данных

**Вариант A: Ручная загрузка**
```
1. Нажмите кнопку "Загрузить данные"
2. Дождитесь завершения загрузки
3. Автобусы появятся на карте
```

**Вариант B: Авто-обновление**
```
1. Нажмите кнопку "Авто-обновление"
2. Данные будут обновляться автоматически
3. Для остановки нажмите "Остановить"
```

### Шаг 3: Навигация по карте

1. **Просмотр автобуса**
   - Кликните на маркер на карте
   - ИЛИ кликните на автобус в списке справа

2. **Информация в popup**
   - Номер автобуса (license plate)
   - Device ID
   - Скорость
   - Координаты
   - Статус движения
   - Время последнего обновления

3. **Управление картой**
   - Зум: колесо мыши / +/- кнопки
   - Перемещение: перетаскивание мышью
   - Авто-центрирование: загрузка новых данных

## 📊 Интерпретация данных

### Статусы автобусов

| Индикатор | Статус | Условие |
|-----------|--------|---------|
| 🟢 | В движении | speed > 0 |
| 🔴 | Остановлен | speed = 0 или null |

### Цвета маркеров

- **Зеленый** - автобус движется (speed > 0)
- **Синий** - автобус остановлен

### Координаты

- **Широта (Latitude)**: -90 до +90
- **Долгота (Longitude)**: -180 до +180
- **Точность**: 6 знаков после запятой (~0.1 метра)

## 🐛 Troubleshooting

### Проблема 1: "Ошибка: Failed to fetch"

**Причина:** Backend не запущен или недоступен

**Решение:**
```bash
# Проверить что backend запущен
curl http://localhost:8080/api/vehicles/positions

# Если нет - запустить
./mvnw spring-boot:run
```

### Проблема 2: "HTTP 404"

**Причина:** Неправильный endpoint URL

**Решение:**
- Проверить правильность URL
- Убедиться что API endpoint существует
- Проверить application.yml конфигурацию

### Проблема 3: Автобусы не отображаются на карте

**Причина:** Нет GPS координат или неверные координаты

**Решение:**
```sql
-- Проверить данные в БД
SELECT license_plate, current_latitude, current_longitude
FROM vehicles
WHERE current_latitude IS NOT NULL
LIMIT 10;
```

### Проблема 4: CORS ошибка

**Причина:** Backend не разрешает запросы с file:// протокола

**Решение:**
```bash
# Запустить локальный HTTP сервер
python3 -m http.server 8000

# Открыть http://localhost:8000/gps-test-map.html
```

## 📈 Мониторинг производительности

### Метрики для отслеживания

1. **Время загрузки**
   - Открыть DevTools (F12)
   - Вкладка Network
   - Смотреть время ответа API

2. **Частота обновлений**
   - Следить за "Последнее обновление"
   - Не должно быть задержек > интервала обновления

3. **Количество маркеров**
   - Оптимально: до 100 маркеров
   - При > 200 может быть медленно

## 🚦 Best Practices

1. **Интервал обновления**
   - Для разработки: 30-60 секунд
   - Для продакшна: 10-30 секунд
   - Не ставить < 5 секунд (нагрузка на API)

2. **Количество автобусов**
   - Начинайте с малого (10-50)
   - Проверяйте производительность
   - Увеличивайте постепенно

3. **Оптимизация**
   - Используйте фильтры API (limit, active)
   - Не загружайте все данные сразу
   - Кэшируйте результаты где возможно
